# Posters

Rotating posters in the world that can be updated without re-uploading the world.

**How it works:** the world holds a fixed pool of 80 URLs (`poster1.jpg` … `poster80.jpg` on GitHub Pages). A GitHub Action fills `Posters/served/` from `Posters/originals/` and writes `count.txt`, the number of posters that actually exist. `Poster` reads that count and only picks from the posters that exist.

Posters are synced: the instance owner picks each poster a full interval ahead, every player downloads it in advance, and everyone swaps at the same moment. Late joiners get the current posters when they join.

Images are downloaded by a single **PosterCache** object in the scene, which every poster shares. Each player downloads each image **once per visit**, and the cache keeps it for every later appearance on any poster. Once a player has the whole set, which takes about 5 seconds per poster, every swap is instant. The cache is added and linked automatically (see [PosterCache](#postercache)).

```
Posters/originals/   <- you put poster images here (source of truth)
Posters/served/      <- generated by the workflow, never edit by hand
    poster1.jpg ... posterN.jpg
    count.txt
```

## Setting up a poster in Unity

### 1. Create the poster surface
1. **GameObject → 3D Object → Quad**, and name it something like `Poster`.
2. Scale it to match the poster aspect ratio. Served posters are **857 × 2048** (about 0.42 : 1), so for example:
   - Scale `X = 0.84`, `Y = 2`, `Z = 1`
3. Remove the **Mesh Collider** if players shouldn't bump into it.

### 2. Give it a material
1. Create a material (**Assets → Create → Material**), for example `PosterMat`.
2. Set the shader to **ClubElementum/PosterCrossfade** (`Assets/Shaders/PosterCrossfade.shader`). It's unlit, so the poster stays bright regardless of scene lighting, and it crossfades between posters.
   - Using a plain shader such as Unlit/Texture instead? Set **Fade Duration** to `0` on the script to get instant swaps.
3. Put `Assets/Textures/PosterLoading.png` (the "Loading posters" card) in **Current Poster**. It shows until the first poster downloads, then fades out. To regenerate it, run `python Tools/make_loading_card.py` (needs `pip install pillow`).
4. Drag the material onto the Quad.

### 3. Add the script
1. Select the Quad and click **Add Component → Udon Sharp Behaviour**. Then assign the `Poster` program asset, or just search **Poster** in Add Component.
2. Drag the Quad's own **Mesh Renderer** into **Target Renderer**.

### 4. Generate the URL pool
1. Right-click the **Poster** component header (or click its ⋮ menu).
2. Choose **Generate URL Pool**.
3. Check that **Image Urls** now has 80 entries (`.../served/poster1.jpg` to `.../poster80.jpg`) and **Count Url** is set to `.../served/count.txt`.

You only need to do this once per poster object. It's saved with the scene.

### 5. Inspector settings

| Field | Default | What it does |
|---|---|---|
| Target Renderer | *(required)* | Renderer whose material receives the downloaded poster. |
| Material Index | `0` | Which material slot on that renderer shows the poster. On PosterStand, `1` = front and `2` = back. |
| Image Urls | *(generated)* | The URL pool. Don't edit by hand; use **Generate URL Pool**. |
| Count Url | *(generated)* | URL of `count.txt`. |
| Change Interval | `30` | Seconds between changes on each poster. Images are cached after their first download, so this can be short. See [Multiple posters](#multiple-posters). |
| Interval Jitter | `5` | Up to this many extra random seconds per change, so posters drift out of sync. |
| Cache | *(auto)* | The scene's **PosterCache**. Added and filled in automatically on Play and before each build. |
| Auto Link By Material | on | Fills **Avoid Same As** automatically, on Play and before each VRChat build, with every other Poster whose slot uses the same material. Turn off to set it by hand. |
| Avoid Same As | *(auto)* | Other Poster components not to duplicate. If it ends up empty, it uses the other Poster components on the same GameObject. |
| Material Texture Name | `_MainTex` | Texture slot on the shader. Change it only if your shader uses a different name. |
| Fade Duration | `1.5` | Seconds to crossfade to the next poster. `0` = instant swap (use this with non-crossfade shaders). |
| Next Texture Name | `_NextTex` | Crossfade shader's incoming-poster slot. Leave as is. |
| Blend Property Name | `_Blend` | Crossfade shader's 0–1 blend value. Leave as is. |
| Debug Logging | on | Writes each pick, sync update and swap to the VRChat log (`output_log`). Turn off before publishing. |
| Base Image Url | `https://skully5000.github.io/ClubElementum/Posters/served/poster` | Generator only: URL prefix. |
| Pool Size | `80` | Generator only: number of URLs. **Must match `POOL_SIZE` in `.github/workflows/build-posters.yml`.** |
| Image Extension | `.jpg` | Generator only. Must match what the workflow serves. |
| Count File Url | `.../Posters/served/count.txt` | Generator only. |

### 6. Test
- Enter Play mode with **ClientSim**. The Console should show no `[Poster]` errors, and the poster should change every *Change Interval* seconds.
- Upload the world. `*.github.io` is on VRChat's trusted URL list, so players don't need "Allow Untrusted URLs" turned on.

### Using the PosterStand model (double-sided)
`Assets/Models/PosterStand.fbx` is a free-standing, double-sided poster stand, about 0.81 m wide and 1.95 m tall. Each poster panel is 0.711 × 1.70 m, the exact poster aspect ratio. It has three material slots:

| Slot | Name | Use |
|---|---|---|
| 0 | Frame | Black frame, neck and base. Any dark material. |
| 1 | Poster_Front | Front poster (faces the stand's local −Z). |
| 2 | Poster_Back | Back poster. |

1. Drag `PosterStand` into the scene.
2. Make two crossfade materials (for example `PosterFrontMat` and `PosterBackMat`) and assign them to slots 1 and 2. Assign a dark material to slot 0.
3. Add **two** Poster components to the stand (or to child objects). Set **Target Renderer** to the stand's Mesh Renderer on both, and set **Material Index** to `1` on one and `2` on the other. Run **Generate URL Pool** on each.
4. Leave **Auto Link By Material** on. Every Poster using the same material (across all stands) avoids showing the same image as the others, as far as the number of available posters allows. To group posters differently, give each group its own material. To run the linking manually, use **Tools → Posters → Link Posters**.

To change its size or shape, edit the dimensions at the top of `Tools/build_poster_stand.py` and run `python Tools/build_poster_stand.py`. Add `--preview <folder>` to render check images.

### Multiple posters
Duplicate the configured poster object. Each poster shuffles the full set and shows every poster once before repeating, starting from a random one. Posters sharing a material are linked automatically so they avoid duplicates.

VRChat lets **each player** download only **one image every 5 seconds** for the whole world. Thanks to the cache, that only matters until a player has every poster: about 2–3 minutes for 27 posters. During that time a swap can wait a few seconds for its image. After that, the number of stands and the *Change Interval* don't affect downloads at all. Linked posters also swap at least 6 seconds apart, so a newly arrived player's downloads never pile up.

### PosterCache
One per scene. It downloads every poster image once per visit, most urgent first, and shares it with all Posters. When nothing is urgent, it downloads the rest of the set ahead of time. It's created automatically, as a `PosterCache` object, the first time you enter Play mode or build with posters in the scene. Save the scene afterwards to keep it.

| Field | Default | What it does |
|---|---|---|
| Max Cached | `40` | Most images kept in memory. Past this, the least recently shown image that no poster is using is freed, and downloaded again if it comes back. Each 857 × 2048 poster takes about 9 MB, so 27 posters are about 250 MB. |
| Retry Delay | `10` | Seconds before retrying an image that failed to download. |
| Download Timeout | `60` | Seconds before giving up on a download that never finishes, so it can't hold up the rest. |
| Debug Logging | on | Writes each download, load and freed image to the VRChat log (`output_log`). Turn off before publishing. |
| Posters | *(auto)* | Every Poster in the scene. Filled automatically. |

If stands were set up with **Generate URL Pool** in the scene rather than on the prefab, use **Tools → Posters → Regenerate URL Pools** after changing a generator setting (such as **Image Extension**) to update every Poster in the open scenes.

## Adding and removing posters (no world update needed)

1. Add or delete image files in `Posters/originals/` (png, jpg, jpeg or webp; any size).
2. Commit and push to `main`.
3. The **Build Served Posters** workflow runs automatically:
   - It resizes each image to fit within 2048 × 2048 (the VRChat limit) while keeping the aspect ratio.
   - It saves them as JPG (quality 90, about a fifth of the PNG size) named `poster1.jpg`, `poster2.jpg`, … in alphabetical order of the originals. Originals and templates are never changed.
   - It updates `count.txt` and commits the result.
4. GitHub Pages redeploys. New posters appear in-world within a few minutes, including in running instances, because the count is re-read every cycle.

You can also re-run the workflow manually from **Actions → Build Served Posters → Run workflow**.

### Going beyond 80 posters
1. Raise `POOL_SIZE` in `.github/workflows/build-posters.yml`.
2. Raise **Pool Size** on each Poster, then run **Generate URL Pool** again.
3. Re-upload the world. This is the only change that needs one.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `Failed to load poster count` | `count.txt` isn't live yet. Check that the workflow and **pages build and deployment** runs succeeded in Actions. |
| `Failed to load image` | The image is over 2048 px (it didn't go through the workflow) or the URL is wrong. Re-run **Generate URL Pool**. |
| `targetRenderer is not assigned!` | Drag the Mesh Renderer into **Target Renderer**. |
| Poster never changes | `count.txt` is `1`, or *Change Interval* is very long. |
| Poster pops instantly or turns white during a change | The material isn't using **ClubElementum/PosterCrossfade**. Switch the shader, or set **Fade Duration** to `0`. |
| Poster stretched | The Quad scale doesn't match 857 × 2048. See step 1. |
| Old poster still shows after an update | GitHub Pages cache (about 10 min). Wait, then rejoin. |
| Players see different posters for a while after a change | Normal for a couple of minutes after someone joins, while their cache fills. With **Debug Logging** on, the log shows `waiting for download` for those swaps. If it keeps happening later, look for `[PosterCache]` errors, or posters being freed because **Max Cached** is lower than the number of posters. |
| `has no PosterCache` | The posters weren't linked. Enter Play mode or build once, or use **Tools → Posters → Link Posters**, then save the scene. |
| Every poster fails to load after the JPG switch | The world still has `.png` URLs. Set **Image Extension** to `.jpg` and run **Generate URL Pool**, or **Tools → Posters → Regenerate URL Pools**. |
