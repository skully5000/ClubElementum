# Dancer Posters

Rotating posters in the world that can be updated without re-uploading the world.

**How it works:** the world holds a fixed pool of 80 URLs (`poster1.png` … `poster80.png` on GitHub Pages). A GitHub Action fills `Posters/served/` from `Posters/originals/` and writes `count.txt`, the number of posters that actually exist. `DancerPoster` reads that count and only picks from the posters that exist.

```
Posters/originals/   <- you put poster images here (source of truth)
Posters/served/      <- generated by the workflow, never edit by hand
    poster1.png ... posterN.png
    count.txt
```

---

## Setting up a poster in Unity

### 1. Create the poster surface
1. **GameObject → 3D Object → Quad**, and name it something like `DancerPoster`.
2. Scale it to match the poster aspect ratio. Served posters are **857 × 2048** (about 0.42 : 1), so for example:
   - Scale `X = 0.84`, `Y = 2`, `Z = 1`
3. Remove the **Mesh Collider** if players shouldn't bump into it.

### 2. Give it a material
1. Create a material (**Assets → Create → Material**), for example `DancerPosterMat`.
2. Set the shader to **Unlit/Texture**, or any shader with a `_MainTex` slot. Unlit keeps the poster bright regardless of scene lighting.
3. Optionally assign a placeholder texture (such as the club logo). It shows until the first poster finishes downloading.
4. Drag the material onto the Quad.

### 3. Add the script
1. Select the Quad and click **Add Component → Udon Sharp Behaviour**. Then assign the `DancerPoster` program asset, or just search **DancerPoster** in Add Component.
2. Drag the Quad's own **Mesh Renderer** into **Target Renderer**.

### 4. Generate the URL pool
1. Right-click the **DancerPoster** component header (or click its ⋮ menu).
2. Choose **Generate URL Pool**.
3. Check that **Image Urls** now has 80 entries (`.../served/poster1.png` to `.../poster80.png`) and **Count Url** is set to `.../served/count.txt`.

You only need to do this once per poster object. It's saved with the scene.

### 5. Inspector settings

| Field | Default | What it does |
|---|---|---|
| Target Renderer | *(required)* | Renderer whose material receives the downloaded poster. |
| Image Urls | *(generated)* | The URL pool. Don't edit by hand; use **Generate URL Pool**. |
| Count Url | *(generated)* | URL of `count.txt`. |
| Change Interval | `30` | Seconds between random poster changes. |
| Material Texture Name | `_MainTex` | Texture slot on the shader. Change it only if your shader uses a different name. |
| Base Image Url | `https://skully5000.github.io/ClubElementum/Posters/served/poster` | Generator only: URL prefix. |
| Pool Size | `80` | Generator only: number of URLs. **Must match `POOL_SIZE` in `.github/workflows/build-posters.yml`.** |
| Image Extension | `.png` | Generator only. |
| Count File Url | `.../Posters/served/count.txt` | Generator only. |

### 6. Test
- Enter Play mode with **ClientSim**. The Console should show no `[DancerPoster]` errors, and the poster should change every *Change Interval* seconds.
- Upload the world. `*.github.io` is on VRChat's trusted URL list, so players don't need "Allow Untrusted URLs" turned on.

### Multiple posters
Duplicate the configured poster object. Each copy picks independently. VRChat allows only **one image download every 5 seconds across the whole world**, so with many posters, keep *Change Interval* at least `5 × number of posters`. Otherwise the downloads queue up.

## Adding and removing posters (no world update needed)

1. Add or delete image files in `Posters/originals/` (png, jpg, jpeg or webp; any size).
2. Commit and push to `main`.
3. The **Build Served Posters** workflow runs automatically:
   - It resizes each image to fit within 2048 × 2048 (the VRChat limit) while keeping the aspect ratio.
   - It renames the images to `poster1.png`, `poster2.png`, … in alphabetical order of the originals.
   - It updates `count.txt` and commits the result.
4. GitHub Pages redeploys. New posters appear in-world within a few minutes, including in running instances, because the count is re-read every cycle.

You can also re-run the workflow manually from **Actions → Build Served Posters → Run workflow**.

### Going beyond 80 posters
1. Raise `POOL_SIZE` in `.github/workflows/build-posters.yml`.
2. Raise **Pool Size** on each DancerPoster, then run **Generate URL Pool** again.
3. Re-upload the world. This is the only change that needs one.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `Failed to load poster count` | `count.txt` isn't live yet. Check that the workflow and **pages build and deployment** runs succeeded in Actions. |
| `Failed to load image` | The image is over 2048 px (it didn't go through the workflow) or the URL is wrong. Re-run **Generate URL Pool**. |
| `targetRenderer is not assigned!` | Drag the Mesh Renderer into **Target Renderer**. |
| Poster never changes | `count.txt` is `1`, or *Change Interval* is very long. |
| Poster stretched | The Quad scale doesn't match 857 × 2048. See step 1. |
| Old poster still shows after an update | GitHub Pages cache (about 10 min). Wait, then rejoin. |
